| 项 | 值 |

## 1. ★ 核心发现：修边不是靠 autotile，是靠"独立修边层"

这是解决用户反复抱怨"修边没整好"的**最关键答案**。统计 BC381 的 Ground 图层各瓦片集占比：

| 瓦片集 | 占比 | 作用 |
|---|---|---|
| `export_ground` | 53.0% | 基础地形（草地/悬崖/土） |
| **`草修边`** | **36.5%** | **专门的"草边修整"瓦片，压在地形边界上做干净过渡** |
| `星空木板` | 7.1% | 装饰性小径/纹路 |
| `草` | 2.8% | 草地细节点缀 |
| `1713590049774`(14px 叠层) | 0.4% | 细节叠加 |
| `木板` | 0.1% | 木板纹路 |

**结论**：整张图 **超过 1/3 的面积是显式修边瓦片**。作者先铺基础地形，再把所有"草↔非草"边界格覆盖成对应的 `草修边` 过渡瓦片（`terrain=1,1,1,0` 这类"三角草+一角异类"）。

`草修边` 瓦片的 terrain 定义佐证（前几块）：
```
id 13 terrain=0,0,0,0   id 9 terrain=1,1,1,0   id 10 terrain=1,1,0,0
id 11 terrain=1,1,0,1   id 12 terrain=1,0,1,0  id 14 terrain=0,1,0,1
```
全部是"草占若干角、异类占其余角"的**边缘过渡专用瓦片**。

### 对我们生成器的可迁移方案
- 方案 A（推荐，最稳）：地形铺完后，对所有"可绘制地块 ↔ 异类地块"的 4 邻/对角边界格，**显式覆盖一层边缘过渡瓦片**（草地用 `草修边` 风格，沙/土/水各自用对应边）。这比单纯依赖 `autotile()` 选角可靠得多。
- 方案 B：确认 `地面层整合.tsx` 是否本身就含足够丰富的边缘瓦片；若含，则保证 `autotile()` 在所有边界都选到正确的 edge 变体，而不是退化为全填充块。
- **绝不**只铺一层基础地形就交差——那正是"简陋 + 修边差"的成因。

## 1.5 视觉文本描述（供无图 AI 复刻观感 · 越细越好）

> 说明：BC381 压缩包只含 `.tmx`（无 tileset 贴图），我**无法看到像素**。以下描述基于 §0~§1 的图层/瓦片数据统计 + RW 1.15 地形的通用观感惯例推断，是"无图 AI 也能据此做出同风格"的文本依据。凡涉及确切色值处标注"（惯例推断）"。

**整体基调**：一张**暖色边境草原**主题的大战场图。远看不是均匀绿地，而是**层层叠叠、边界分明、有厚重立体感**的手工地貌——这是它与"程序化平铺草地"最本质的观感差别。

**逐元素文字刻画**：

- **草地主体（占基础地形 ~44%）**：中等明度的**黄绿色**（惯例推断约 `#7a9a4e` 一带），不是鲜亮纯绿。大片草地中存在由 `草` 细节瓦片（占全图 2.8%）带来的**明暗斑驳**——同色系里有略深略浅的草丛变化，打破死板均匀。
- **悬崖屏障（Cliff，占基础地形 ~6.8%）**：**近黑的深灰岩壁**（惯例推断 `#3a3a3a`~`#2a2a2a`），呈**连续锯齿状山体/峡谷壁**，既是地图外缘的"世界边界"，也是内部把战场切分的多道山脊。它**不可通行**，所以读图时玩家感知为"厚重的石头城墙"。
- **泥土斑块（Dirt，~2.4%）**：**棕褐色**（惯例推断 `#8a6a44`）的不规则土块，散布在草地与悬崖之间，制造"踩出来的小路/焦土"质感。
- **★ 草边修整层（占全图 36.5%，观感灵魂）**：在**每一处"草地↔异类"边界**（草↔悬崖、草↔泥土、草↔水）上，都铺了一圈**略深于草地的过渡瓦片**，形成**干净、连续、无阶梯锯齿的描边**。这就是 BC381 边缘"看起来很整齐"的真正原因——不是 autotile 自动拼出来的，是**人工覆盖的边缘层**。无图 AI 复刻时：铺完基础地形后，必须对所有边界格再覆盖一层"深色草地边"瓦片。
- **装饰小径（`星空木板`，占 ~7.1%）**：细带状的**木板/星空纹路**贴图，像地图上被人踩出的**小道/河流栈道**，横穿草海，提供视觉引导线，避免大块空旷。
- **资源点**：金属质感的开采节点**成片聚集**（共 10 种、210 格），不是孤点；水晶是**区别于普通矿的发光标记**，每队专属（GID 1570~1573）。读图观感是"几片富矿区 + 零星水晶"。
- **留白与密度**：地图巨大（435×425），但**没有大块纯色空地**——草地里永远嵌着泥土斑、草细节、小径、边缘描边，所以"满而不乱"。

**一句话给无图 AI 的复刻目标**："暖色草原底色 + 近黑锯齿悬崖做屏障 + 每道地形边界都描一圈深色草边 + 泥土斑和木板小径打破均匀 + 资源成片"。照这五条做，观感就会从"简陋平铺"跃迁到"手工地貌"。

## 2. 地形词汇表（职业图真正在用的 12 类）

`export_ground` 的 `<terraintypes>` 定义了完整调色板（按索引顺序）：

```
0 DeepWater  1 Water  2 ShallowWater  3 WaterBridge
4 Sand       5 Grass  6 Dirt          7 Snow
8 Stone      9 Lava   10 Tree         11 Cliff
```

> **注意 Snow / Lava / Tree / Cliff 这 4 类是我们之前做图几乎没用过的**。职业图靠它们制造"主题地貌"和"不可通行屏障"。
> 我们之前只用了 草地/土/石/沙/泥/水/高石/高草 —— 词汇太贫乏，是"简陋"的又一主因。

BC381 基础地形（`export_ground` 部分）实际分布：
```
Grass   43.7%    Cliff  6.8%    Dirt  2.4%    Stone 0.1%    WaterBridge 0.0%
```
- **Cliff（悬崖）占 6.8%**，是主要"不可通行屏障"；**不是用 Stone/高石**。
- 这张图**几乎无水**（WaterBridge≈0），是纯陆地战图（"边国远畿"题材）。
- 启示：**用 Cliff/高石做屏障时，给到 ~5~8% 的面积才够"有地形起伏"**，我们之前高石太零星。

## 3. 资源密度（"丰富"的量化标准）

| 项 | BC381 数值 | 我们 4V4 图 |
|---|---|---|
| 资源瓦片种类 | **10 种**（GID 217~239） | 单一 `res` |
| 资源总格数 | **210 格** | 16 起步矿 + 少量水晶 |
| 水晶 | 每队专属（GID 1570~1573，各 14） | 7 个共享水晶 |
| 起步矿/队 | 多矿（资源格密集成片） | 2 矿/队 |

> 启示：职业图资源是**成片、多类型、密集分布**的，不是稀疏几个点。即使做竞技平衡图，也要把资源做成"几片矿脉"而非"孤零零 2 个矿"。

## 4. 机制丰富度（对纯遭遇战是"上限标尺"，不直接套用）

- Triggers 图层 **4799 个对象**，命名全是历史主题事件：`Add东出燕山 / Add稷下学宫 / Add吴起变法 / Add勒索匈奴 / Add统一匈奴 / Add秦霸西戎 / Add桓公复国` 等。

> 对**纯遭遇战（零触发器）**图：不抄机制，但抄"密度感"——用地形层次、资源成片、视觉装饰来营造丰富度，而不是用脚本。

## 5. 可迁移原则清单（给未来做图的 AI）

1. **修边必须显式做**：铺完基础地形后，独立覆盖一层边缘过渡瓦片（草地 `草修边` 风格）。占比应达全图 **25~40%** 才够"不糙"。
2. **地形词汇要全**：至少用到 Grass/Dirt/Sand/Stone/Cliff/Tree + 一种主题地貌（Snow 或 Lava 或 泥沼），别只铺草地。
3. **屏障用 Cliff/高石占 5~8% 面积**，做成连续山体/孤峰，而不是零星碎块。
4. **资源成片多类型**：起步矿做成几片矿脉；水晶放在"需争夺"的位置（岛/桥/隘口），让海陆军主导。
5. **空间要慷慨 + 密度要高**：单位/装饰铺满，避免大块均匀空地。
6. **叠加装饰层**：小径(`木板`/`星空木板`)、草地细节(`草`)、枯木/岩石点缀，制造层次。
7. **风格要拉开**：每张新图选不同主题（海峡/裂谷/雪原/火山/群岛），调色板、屏障形态、植被都换，避免"长得都像"。

## 6. 避坑：解析 RW 1.15 地图的压缩格式

BC381（及多数 1.15 导出图）的图层数据是 `encoding="base64" compression="zlib"`，**不是 gzip**：

```python
import base64, zlib, struct
raw = base64.b64decode(data_text)
dec = zlib.decompress(raw)           # ← 用 zlib，不是 gzip
gids = list(struct.unpack('<%dI' % (len(dec)//4), dec))
grid = [[gids[r*W+c] for c in range(W)] for r in range(H)]
```
地形类别反推：`tile_id = gid - firstgid` → 查 tileset 中该 `<tile>` 的 `terrain="a,b,c,d"`（4 角类型）→ 多数角即该格主地形。

> 对照：我们自己的生成器输出的是 gzip，解析自己的图用 `gzip.decompress`；**解析别人/社区下载的图先用 zlib 试**。

## 7. 一句话总结

> 我们之前"简陋 + 修边差"的根因不是公式错，而是**只铺了一层基础地形、地形词汇只有 6 类、屏障太碎、资源太稀**。职业图用"独立修边层(36.5%) + 12 类地形词汇 + 成片多型资源 + 慷慨空间"把这些都做满了。照这 5 条原则重做，观感会质变更。
