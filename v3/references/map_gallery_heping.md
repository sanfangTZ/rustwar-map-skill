# 参考图库 · 和平铁锈「时代图精品合集」拆解（10P~18P 历史混战图）

> **本文件目的**：把用户提供的真实社区好图，转成**详尽的中文文字描述**沉淀进 skill。
> 不存储任何图片/地图原件；无识图能力的 AI 也能凭本文复刻其设计要点。
> 来源：`和平铁锈时代图精品合集.zip`（8 张历史主题自由混战图，作者「和平铁锈」）。
> 解析约束：RW 1.2 格式，每张图**自带独立 tileset**，图层数据用 **gzip 或 zlib** 压缩（见 §5 避坑）。

---

## 0. 一句话总览：这批图和我们之前做的图，根本不是一类

我们之前做的 4V4（海峡图/裂谷图）是**抽象对称竞技图**：左右镜像、团队分队、纯遭遇战。
和平铁锈这批是**地理写实自由混战图**：

- 复刻真实大陆轮廓（伊比利亚半岛、地中海、中东、明末中国……），**不是对称设计**
- 每张图 **10~18 个玩家**，各占一块真实地域，玩家出生点**散布全图**而非抱团
- 核心玩法是**夺城**（几十座中立城防 + 城市对象），不是纯出生点对抗
- 触发器 **1263~6310 个**（海量脚本驱动历史事件/奖励）——这是"好玩"的来源
- 资源**又多又杂**（270~900 格、9~18 种），每玩家领地内成片分布
- 地形词汇**极丰富**（8~19 类，且同一基色有多档明暗），看起来有层次、不扁平

**可迁移的结论**：做"好看/好玩"的图，要向这批图学——地理写实轮廓、明暗分档地形、慷慨资源、夺城机制、脚本密度。但竞技对称图（4V4）仍应镜像对称（见 `competitive_4v4.md`），二者目标不同，不要混用标准。

## 2. 跨图归纳：可迁移的"好图"设计法则

把八张图共性提炼成规则，任何 AI 做图都照此自检：

### 法则 A · 地理写实轮廓 > 抽象对称
历史/大陆图用**真实地貌剪影**（半岛、内海、山脉脊线、河谷）。它会自然产生**不对称的 chokepoint 与航道**，比硬画对称更有张力。
→ 实现：先用 SDF/噪声画"陆地 silhouette"，再在边界上做海陆过渡，而不是铺满均匀地形。

### 法则 B · 地形要"明暗分档"，拒绝扁平
好图同一基色有 **3~5 档**（草：草地正常/草地1/浅草0~3；沙：正常/1~3；山：山/山1~3）。这是"有层次、不简陋"的核心。
→ 实现：每个 base 地形配 3+ 档噪声阈值，按噪声值选不同 tile，制造斑驳质感。

### 法则 C · 地形词汇要全（8~19 类）
本批图用到：水(深/浅/桥)、沙/沙丘、草/浅草、泥、雪、冰/冻树/冰湖、沼泽、熔岩、山/高山/崖、树、石、仙人掌、坑洞……远多于我们常用的 6 类。
→ 实现：至少覆盖 水/浅水/沙/草/泥/雪/山/崖/树 九类，极端主题再加 冰/熔岩/沼泽。

### 法则 D · 屏障靠山脉/悬崖成"带"，不要零星高石
好图用**连绵山体（6%~33% 面积）**当天然墙与领地分界，而非我们之前"几座孤立方山"。
→ 实现：用低频连续噪声生成山脉带（脊线 + 半宽），保证 4-连通、无碎段（见 `edge_cleanup.md`）。

### 法则 E · 水资源是主角，不是边角
本批图 **水占 24%~36%**，常是地图中央的内海/河道（配"水桥"做 chokepoint）。
→ 实现：把水域做成结构性要素（中央海峡/内海/大河），而非只在四周描一圈。

### 法则 F · 资源又多又杂、每玩家领地内成片
本批 **270~900 资源格**，分 **9 或 18 种**，每玩家领地内**成片密布**（起步矿是矿脉不是孤矿）。
→ 实现：每玩家 2~3 处密集矿脉（每处 10~30 格同类），而非 2 个孤矿；资源种类 ≥ 6 种。

### 法则 G · 夺城机制是"好玩"的灵魂
本批图都有**几十座中立城防（team=-2/-1）** + `城市` 对象组（38~105 座），玩家争夺历史名城。
→ 实现：自由混战/历史图必做夺城链（城毁→刷中立总部，同古巴 `gen_cuba.py` 的城夺玩法）。

### 法则 H · 脚本密度决定"好玩"上限
触发器 **1263~6310 个**。这些驱动历史事件、奖励、区域 buff 等，是社区好图区别于"裸图"的关键。
→ 实现：除纯竞技图外，至少加区域事件/奖励触发器，别只放 map_info。

## 4. 给"做新图"的复刻目标清单

做一张"像社区好图"的历史/地理混战图时，逐项自查：
1. [ ] 地形是**地理写实轮廓**（半岛/内海/山脉脊线），不是均匀铺满
2. [ ] 每个 base 地形有 **≥3 档明暗**（噪声分档）
3. [ ] 地形词汇 **≥8 类**（含 水/浅水/沙/草/泥/雪/山/崖/树）
4. [ ] 山脉/悬崖成**连续带**当屏障（面积 6%~33%），非孤立点
5. [ ] 水域是**结构性要素**（中央海/河 + 水桥 chokepoint），占 24%~36%
6. [ ] 每玩家领地内有 **2~3 处密集矿脉**，资源种类 ≥6，总量随地图放大
7. [ ] 做了**夺城机制**（中立城防 + 城市对象 + 城毁刷中立总部链）
8. [ ] 加了**足量脚本**（历史事件/奖励/区域 buff），触发器 ≥ 数百
9. [ ] 玩家出生点**按真实地域散布**，各占一块（自由混战），或镜像对称（竞技队战）

## 5. 解析社区地图的避坑（其他 AI 读别人图时必看）

社区 .tmx 约定**极其混乱**，解析脚本必须**约定无关**：

1. **图层名大小写不一**：`items`/`Items`、`units`/`Units`、`unitObjects`/`UnitObjects` 都出现过 → 比较时 `.lower()`。
2. **压缩方式混用**：有图 `gzip`，有图 `zlib` → `decompress` 先试 gzip 失败再 zlib 兜底（见 `pro_map_reference.md` 的 zlib 坑）。
3. **tileset 可能无 terraintypes**：如 11P(export_items)、13P(None) → 用"GID→四角 terrain→多数类"推断调色板会整张 `?`，此时改从图层名/瓦片集名猜主题。
4. **一张图可引用多个 tileset**，或 Ground 引用的 tileset 不在首位置 → 用 `firstgid` 区间定位，而非取第一个。
5. **出生点字段**：玩家出生 = `commandCenter` 且 `team>=0`；**中立城防 = `commandCenter` 且 `team<0`（多为 -1 或 -2）**，别漏判。
6. **`城市` 对象组可能为 0**：此时夺城目标仅由中立 HQ 表现（如 15P/17P）。
7. **资源在 items/Items 瓦片层用 GID 编码**，每种 GID 计数均衡（如 9 种各 30 格）→ 统计非零 GID 即可知资源密度与种类数。
8. **坐标换算**：object 的 `x/y` 是像素，除以 `tilewidth(20)` 得格坐标。

## 6. 使用边界（重要）

- 本批图是 **1.2 格式、自带 tileset、依赖外部贴图**，**无法用我们的 `地面层整合.tsx` 管线直接渲染**（缺贴图）。它们作为**设计参考**，不是可直接改的模板。
- 做新图时**借鉴其布局/调色/机制设计**，地形 tile 仍走我们的 `地面层整合.tsx` + `autotile()`（见 `terrain_generation.md`），或自建对应词汇的 tileset。
- 切勿把本 zip 或其中 .tmx 塞进 skill 当素材——它们是第三方地图，应作为"设计启发"消化为上述文本规则。
